## 引言（做什么 / 为什么）

Phase 0 验证本项目策划书依赖的三条硬事实，全部通过后进入 M2 骨架开发：

1. **VPN 可不可用** —— HarmonyOS NEXT 三方 VPN（虚拟网卡 + 路由 + DNS 接管）在 API 26 真机上的实际表现；
2. **内核编不编得进** —— Go c-shared → OpenHarmony `.so` 工具链是否打通，能否加载一次真实内核（overshoot 目标）或至少加载最小 .so + NAPI；
3. **回收扛不扛得住** —— VPN 进程后台保活（官方长时任务 / 内核前台模式 / 回收自恢复）实测是否成立（ClashBox 实证的痛点）。

产出 `PoC-REPORT.md`（结论 + 证据 + 三态），供 M0 立项评审使用。

## 任务清单

### T1. VPN 能力复核（真机实测）

**目标**：确认 `@ohos.net.vpnExtension`（API 26）在真机上能建虚拟网卡 / 配路由 / 配 DNS，主机系统流量被接管；复核"系统 HTTP 代理 / 应用内透明接管"对三方不可用。

**步骤**
1. 任意工程注册 VpnExtensionAbility（`type: vpn`），跑通最小"建立连接 + 虚拟网卡 + 路由"；
2. 实测三项接管细节：DNS 配置（nameserver / dns 地址，验证应用内解析被接管）、UDP 转发、IPv4/IPv6 双栈；
3. 实测：系统 HTTP 代理设置 / Firewall 级透明接管对三方应用是否可写（预期不可用，出证据）；
4. 真机本机签发调试证书，完成一次真机安装。

**验收**（满足任一下列给出三态）
- 继续：VPN 建链 + DNS 接管 + UDP + 双栈均可用；
- 收缩：仅 DNS/UDP 部分受限 → 记录受限项，仍可走 VPN 主路径；
- 终止：连 VPN 虚拟网卡都无法建立 → 直接终止并走策划书 2.1 保底形态。

**产出**：`T1-VPN-能力.md`（接管能力矩阵 + 截图 + 崩溃/报错日志）

### T2. Go 交叉编译工具链专项

**目标**：打通 **Go c-shared → OpenHarmony `.so`** 完整工具链（NDK/交叉编译、syscall、网络栈差异），产出可被 NAPI 调用的最小 .so。

**步骤**
1. 用 target `linux/amd64` + OH 工具链产出可加载 .so，跑通 NAPI`hello` 调用；
2. 覆盖真实内核依赖：syscall、网络栈（TCP/UDP/QUIC）、crypto 三类的编译性验证（静态编译一段含网络与加密的最小内核片段）；
3. 对照 ClashBox 的 FLclash 实现路径，记录可复用的工具链/构建脚本/坑；
4. 记录构建产物体积、加载耗时、崩溃面。

**验收**
- 继续：最小 .so + NAPI 调用成功，网络/加密片段可编译；
- 收缩：仅部分依赖阻塞 → 记录降级路径（裁剪库 B1）；
- 终止：工具链完全不可用 → 走 B1 / 保底。

**产出**：`T2-工具链.md`（构建脚本、目标/约束、体积、结论）

### T3. 内核实载与保活专项（最高风险，前置）

**目标**：用**一次真实内核**完成"加载 + VPN 接管 + 后台保活 + 回收自恢复"端到端验证，把 ClashBox 的实证痛点提前钉死。

**步骤**
1. 选型：优先 Arkhon 桌面端同源内核（arkhon-core / mihomo）；若工具链受阻则降级现有 FLclash 同类 Go 内核；
2. 达成最小可用：内核 .so 加载 + VPN 隧道联通（导入测试订阅，代理一条真实流量）；
3. 保活基线：接入官方 `KEEP_BACKGROUND_RUNNING` + `backgroundModes: dataTransfer` 长时任务，隧道运行时驻留通知；
4. 保活增强：实现"内核前台模式 + 模拟后台"（对标 ClashBox）；增加回收检测与自动重建；
5. 真机场景：切后台 + 锁屏 30 分钟、被系统回收后，隧道是否存活/自恢复。

**验收**
- 继续：端到端跑通，锁屏 30 分钟存活或回收可自恢复；
- 收缩：保活仅能靠增强方案达成 → 记录并纳入设置项开关；
- 终止：内核无法加载 / 保活无法达成 → 走 B1 / 保底（VPN 单路径不成立则终止立项）。

**产出**：`T3-内核保活.md`（搭建步骤、保活矩阵、回收集日志、结论）——本任务结论优先级最高

### T1 实测 API 事实（回填，供 T2/T3 复用）

1. **生命周期**：`VpnExtensionAbility` 显式回调仅 `onCreate/onDestroy`；`startVpnExtensionAbility(want)` 为 **start 语义 → 建链入口须重写 `onRequest(want, startId)`**（非 onConnect）。
2. **调用形态**：`vpnExtension.createVpnConnection(this.context)`（模块级），`VpnConnection.create(config): Promise<number>` 返回虚拟网卡 fd；`destroy()` 无参（API 20+ 另有过载）。
3. **VpnConfig**：`vpnId` 可选（若重复 create 报 `2203002 VPN exist already`，需幂等：`isUp` 标志或 2203002 视为成功）；`RouteInfo` 必填 `interface/destination/gateway/hasGateway/isDefaultRoute`；`dnsAddresses` 配置即生效。
4. **授权监听**：API 26 提供 `vpnExtension.createVpnObserver()` + `onAuthorizationResult(cb)`，可把弹窗「允许/拒绝」实时反馈到 UI。
5. **错误码**：`2203002`=VPN 已存在；`2200002`=服务未就绪（授权前）；`2203001`=创建被拒（检查 user type）。
6. **UI↔扩展**：前端「已连接」要靠授权回调（VpnObserver）或扩展侧回传，不能本地推断。
