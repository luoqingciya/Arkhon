## 2. 逐项结论与证据

### 2.1 T1 · VPN 能力复核 —— ✅ 继续

**实测（真机 API 26）**
- `vpnExtension` 虚拟网卡建立成功：系统解析 VpnConfig 显示 address `10.21.0.2/32` + route `10.22.0.0/16` + DNS 配置即生效；
- 系统「设置 → VPN」出现 Arkhon 条目，授权弹窗正常；
- 本机签发调试证书 → 真机安装、启动链路跑通。

**关键 API 事实（供实现复用）**

1. 生命周期：`VpnExtensionAbility` 显式回调仅 `onCreate/onDestroy`；`startVpnExtensionAbility(want)` 为 start 语义 → **建链入口须重写 `onRequest(want, startId)`**（非 onConnect）；
2. 调用形态：`vpnExtension.createVpnConnection(this.context)`（模块级）→ `VpnConnection.create(config): Promise<number>` 返回虚拟网卡 fd；`destroy()` 无参；
3. `VpnConfig`：`vpnId` 可选（重复 create 报 `2203002 VPN exist already`，需幂等）；`RouteInfo` 字段必填；`dnsAddresses` 配置即生效；
4. 授权监听：API 26 `createVpnObserver()` + `onAuthorizationResult(cb)` 可把弹窗「允许/拒绝」实时反馈到 UI；但系统记住授权后不再弹窗（回调不触发）→ 运行态须以「VPN 网络出现 + setAppNet 成功」为兜底信号；
5. 错误码：`2203002` 已存在 / `2200002` 服务未就绪（授权前）/ `2203001` 创建被拒；平板实测 `2300007/2300006` 为全量路由受限下的流量不通表现（旧系统；2026-09-28 已在 API 26 复测解除，见 2.4）。

**三态判定**：**继续** —— VPN 接管面成立，引擎 A/B1 的承载路径确认。

### 2.2 T2 · Go 交叉编译工具链 —— 🟢 通过（Gate-B 关闭）

| 分项 | 结论 | 证据 |
| --- | --- | --- |
| 最小 .so 交叉编译 | ✅ | 产出 `aarch64-linux-ohos` ELF64 DYN（导出 `Hello`/`Add`），约 2.6 MB；构建参数：OHOS NDK clang + `--target=aarch64-linux-ohos -D__MUSL__` |
| 网络/加密依赖编译 | ✅ | `llvm-nm -D` 显示 `getaddrinfo/freeaddrinfo` 解析到 **OHOS musl libc**；net/crypto/tls/http 全部编译链接通过（含网络/加密产物约 7.2 MB） |
| NAPI 运行时 dlopen | ✅ **真机通过** | 见下 |

**决定性障碍与正解**

- 障碍：股票 Go c-shared 的 **initial-exec TLS** 在 OHOS musl 的 dlopen 场景下失败（`initial-exec TLS resolves to dynamic definition`）；
- 正解（已实测）：**openharmony-sig/ohos_golang_go** fork（`release-branch.go1.24`，带真 `GOOS=openharmony` 端口，runtime 内置 general dynamic `TLS_GD`）→ 自举出 go1.24.5 宿主重编，`readelf` 复核 TLS 重定位由 `R_AARCH64_TLS_TPREL64` 变为 **`R_AARCH64_TLSDESC`**（musl 可在 dlopen 库上处理的形式）；
- 真机复核：Mate 80 Pro `hilog` 实测 `T2 loaded=1 hello="hello, arkhon" add=5`，initial-exec 报错消失；
- 排除项：`go tool compile -tls=GD` 仅是未合入上游的提案（go#71953）；`harmony-contrib/log-adaptor` 非 TLS 解法。

**三态判定**：**继续（引擎 A）** —— 「内核编不进去」的 No-Go 信号解除；工具链固化为常规构建资产（`experiments/T3-toolchain/build-toolchain.ps1`、`build-hellogo-ohos.ps1`）。

### 2.3 T3 · 内核实载与保活专项 —— 🟢 继续（最高风险项闭环）

**内核实载（Gate-D / D5e，2026-09-13）**

- 内核：自有仓库 **arkhon-core** 的 `clashlib`（Go buildinfo 实测：`arkhon/clashlib v0.9.13-arkhon` · `GOOS=openharmony` · `-tags=with_gvisor` · revision `b860c46`），编为 c-shared `.so` 随 HAP 打包；
- 形态：NAPI 在 **VpnExtensionAbility 进程内**加载，用 `VpnConnection` fd 喂流；gvisor 用户态栈在用户态独立完成 TCP 握手（SYN-ACK 直接写回 fd），绕开 OHOS 沙箱对 `fstat`/raw socket 的限制；
- 闭环证据：`tunnel-out-ip code=200`、`tunnel-out-host code=200`（主进程隧道出网 TCP/域名全链路）；
- 关键配置：gvisor fork replace（`mihomo-teyvat/third_party/gvisor`）+ `IsSocketFD` 改 `getsockopt(SO_TYPE)` 探测 + `TunGvisor` 栈。

**保活专项真机矩阵（Mate 80 Pro · API 26 · 蜂窝 rmnet0，2026-09-28）**

| # | 实验 | 结果 |
| --- | --- | --- |
| 1 | 切后台 + 锁屏 32 分钟（无定期刷新） | ✅ 扩展进程（内核所在）零冻结零重启：心跳 60s × 38 条零断档、pid 不变、`kernel=OK code=200`；TUN `multitun-vpn1` 保持 UP；39 分钟后 `tunnel-egress code=200`。⚠️ 主进程（UI/长时任务宿主）约息屏 11 分钟后被冻结，长时任务被系统取消 |
| 2 | 模拟隧道意外丢失 → 检测 + 自动重建 | ✅ 60~90s 全链路闭环：重启扩展 → 重挂内核 fd → `setAppNet` 重绑新网络 → 出网 200 |
| 3 | 锁屏 + 每 4 分钟刷新长时任务 | ❌ `updateBackgroundRunning` 不能重置「>10 分钟未更新」计时器（任务在第 10.05 分钟被取消）；取消事件 `reason=USER_CANCEL(1)` **在冻结前送达** |
| 4 | **取消即重申请**（收到 `continuousTaskCancel` → 5s 内立即重申请） | ✅ 跨 2 个回收周期零冻结、tick 零断档（实测 43.03 个自检周期 ≈ 理论 43.0）；取得精确回收原因码 `detail=12`（`SYSTEM_CANCEL_DATA_TRANSFER_NOT_UPDATE`） |
| 5 | 静音音频深度保活（`AUDIO_PLAYBACK` + AVSession + 全 0 静音流） | ❌ 被系统专门反制（`WriteMuteDataSysEvent` → `IsAllSessionMute` → Doze/Freeze），长时任务豁免不生效 → **终止（本代系统）**，代码保留默认关闭 |

**三态判定**：✅ **继续**，分项如下：

| 判据 | 结论 | 依据 |
| --- | --- | --- |
| 隧道端到端 + 锁屏 30 分钟存活 | ✅ 继续 | 实验 1（32 分钟全存活） |
| 检测 + 自动重建自恢复 | ✅ 继续 | 实验 2（60~90s 闭环） |
| 主进程后台保活 | ✅ 继续（A 方案：合法自续期，无伪装行为） | 实验 4（跨 2 回收周期零断档） |
| 静音音频强保活 | ❌ 终止（本代系统） | 实验 5（被静音检测反制，不列入产品方案） |

## 5. 引擎路线冻结（决策记录）

**冻结结论：V1.0 引擎 = A（自编内核 .so，与桌面端 arkhon-core 同源）**

| 项 | 内容 |
| --- | --- |
| 形态 | arkhon-core `clashlib`（mihomo fork）c-shared `.so`，NAPI 在 VpnExtensionAbility 进程内加载；`VpnConnection` fd + gvisor 用户态栈 |
| 产物链路 | 内核 CI 自动产出 `arkhon-ohos-arm64-<tag>.so`（随 release），鸿蒙侧 `download-clashlib.ps1 <tag>` 拉取至 `entry/libs/arm64-v8a/` |
| 备选处理 | **B1（裁剪库）不启动**：与 A 同源同语言（Go），仍需同一套 musl 兼容工具链，无成本优势；**C（远端面壳）不参与主线**：违背「原生」目标且离线不可用，仅保留极端兜底 |
| 冻结含义 | 引擎实现不再变更；任何偏离需回到策划书 §7.2 / §2.1 补充决策记录 |

**凭据与合规（随附说明）**

- PoC 期在扩展进程内联的测试节点凭据已从代码与 git 历史清除（含关联仓库历史重写）；**服务端密码轮换仍待执行**（见 §6-5）；
